## 1. Executive Summary

FormFoto is a fully functional, four-vertical photo-compliance web application built with **Next.js 16 (App Router), React 19, TypeScript 5, and Tailwind CSS 4**. It processes images entirely client-side using Canvas APIs and the `@imgly/background-removal` WASM/ONNX model.

The codebase is compact (~3,300 lines of component code across four editors) with a large configuration surface (85 exam specs, 40 passport specs, 18 visa country configs). The four product areas — **Exams, Passports, Visas, Manual** — share significant processing logic but no shared components today: each editor duplicates helper functions, canvas rendering, compression, background removal, dropzone, and overlay code.

The current visual system is a **dark-mode-only, Tailwind-utility-first design** with per-section accent colours (blue, emerald, amber, purple/cyan) and no centralised design tokens. There is no global navigation shell, no shared footer, and no shared layout between the four product areas.

The planned redesign — a light-first, `#315CEA`-accented, token-driven system — is technically feasible and carries **medium risk** overall. The highest risks are:

1. **Canvas coordinate coupling** — crop/resize/compression logic relies on DOM-measured `img.width`/`img.height` vs `naturalWidth`/`naturalHeight`. CSS changes to image containers can silently break output dimensions.
2. **Background-removal lifecycle** — async WASM processing runs inside the component render tree with overlays. Refactoring component boundaries must preserve the loading-state machine.
3. **Print-sheet generation** — BiometricStudio produces a pixel-exact 800×1200 print canvas. Layout changes must not alter the `renderPrintSheet` path.
4. **Generated index files** — three `index.ts` files are auto-generated by Node build scripts. They must not be hand-edited or reformatted.
5. **Visa profile state isolation** — VisaStudioClient manages multi-profile + subclass state that resets on profile change and feeds a keyed `BiometricStudio`. The keying strategy must be preserved.

## 6. Editing Engine Architecture

### 6.1 SmartEditor (Exam Photo Engine)

**File:** [SmartEditor.tsx](file:///d:/Programming/Resizer/formfoto/src/components/SmartEditor.tsx)

**Purpose:** Multi-document exam photo/signature editor with auto-centering, background removal, name/date stamping, and exact KB compression.

**Props:** `{ config: FormatConfig }` — receives the full exam specification including multiple documents.

**Key features unique to SmartEditor:**
- **Document tab switching** (`activeDocIndex`) — supports photo + signature documents
- **Smart crop** via `smartcrop` library — face-detection-based auto-centering
- **Name/date stamp** — canvas overlay for stamping text onto the bottom 15% of the photo
- **`stampRequired` gating** — stamp UI only appears when `activeDoc.stampRequired === true`
- **Dynamic background color** — 3-swatch picker (white, light grey, studio blue)
- **`react-hot-toast`** — only editor using toast notifications

**State machine:**
```
Initial → Upload (onDrop) → Image Loaded (onImageLoad) → Crop Selected
  → [Optional: Smart Crop / Remove BG] → Process & Compress (generateCroppedImage)
  → Pre-Flight Check → Download Available
```

**Output:** Single JPEG at exact `width × height` px, within `minKb–maxKb` range. Filename: `{exam_title}_{doc_id}_FormFoto.jpg`.

**Canvas logic (CRITICAL):**
- `renderCanvas()` (L320–373) — paints background, draws cropped image, optionally draws stamp strip
- Uses `img.width/img.height` (display dimensions) and `img.naturalWidth/naturalHeight` for coordinate mapping
- The `isStampingEnabled` flag alters the photo region to 85% of canvas height

**Zero-dimension fallback:** If `width === 0`, falls back to 413×531 (passport standard). This handles exam configs that specify "any standard passport size."

### 6.2 BiometricStudio (Passport/Visa Engine)

**File:** [BiometricStudio.tsx](file:///d:/Programming/Resizer/formfoto/src/components/BiometricStudio.tsx)

**Purpose:** ICAO/consular-grade biometric photo editor with compliance panel, biometric guide overlay, and dual-output (digital download + print-ready sheet).

**Props:** `{ config: VisaPassportConfig; mode: "passport" | "visa" }`

**Key features unique to BiometricStudio:**
- **Mode-driven colour palette** — emerald (passport) vs amber (visa) accent system
- **Biometric guide overlay** — SVG with crown/eye/chin lines and facial oval, calculated from `config.biometrics`
- **ResizeObserver** — tracks the `imageContainerRef` to position the overlay accurately
- **CompliancePanel** — detailed compliance checklist showing background, dimensions, DPI, glasses, smile, shoulders, face/frame ratio, infant rules, source authority
- **Print-ready sheet** — `renderPrintSheet()` generates a 4×6" @ 200 DPI (800×1200 px) grid with cutting guides
- **Auto-download** — digital export triggers `document.createElement("a").click()` programmatically
- **Pixel dimension derivation** — `derivePixelDimensions()` derives from `digital.minWidthPx/minHeightPx` or calculates from `physical.*mm × targetDpi / 25.4`
- **KB limit derivation** — `deriveKbLimits()` falls back to 50–500 KB if digital config is missing
- **Guide toggle** — eye/eyeOff button controls biometric overlay visibility
- **Pill toolbar** — Change Photo, Remove BG, Guide ON/OFF in a rounded pill bar

**Output:** Two outputs — digital JPEG at derived pixel dimensions, and a print-ready JPEG sheet at 800×1200.

**Canvas logic (CRITICAL):**
- `renderPhotoCanvas()` (L689–715) — simple crop-to-dimensions, no stamp or background fill (background is in the source image after BG removal)
- `renderPrintSheet()` (L721–806) — tiles photos onto a 4×6" sheet with hairline cutting guides and a text label

### 6.3 ManualEditor (Pro Workspace Engine)

**File:** [ManualEditor.tsx](file:///d:/Programming/Resizer/formfoto/src/components/ManualEditor.tsx)

**Purpose:** Fully user-configurable editor with arbitrary pixel dimensions, target KB, JPG/PNG format toggle, and custom background colour.

**Props:** `{ presetConfig?: PresetConfig }` — optional `{ width, height, maxKb }` to lock dimensions.

**Key features unique to ManualEditor:**
- **User-defined dimensions** — width, height, maxKb as editable number inputs
- **Format toggle** — JPG vs PNG (PNG bypasses compression)
- **Background colour palette** — 5 preset swatches + custom colour picker input
- **Transparent background** — checkerboard pattern preview for PNG mode
- **`estimateCapped` state** — shows "Max Quality Reached" when target KB exceeds what quality 1.0 can produce
- **20-iteration bisection** — more precise than SmartEditor's 5-iteration and BiometricStudio's 6-iteration versions
- **No validation** — no minKb/maxKb enforcement on final output (user controls everything)
- **No print sheet** — single-image output only

**Output:** Single JPEG or PNG at `targetWidth × targetHeight` px. Filename: `ManualEditor_{w}x{h}.{ext}`.

## 7. Data and Configuration Flow

### 7.1 Schema Architecture

The codebase uses **two independent schema systems**:

| Schema | Interface | Used By | Config Files | Index |
|---|---|---|---|---|
| **Exam** | `FormatConfig` → `FormatDocument[]` | SmartEditor, exam pages | 85 files in `src/config/exams/` | `src/config/index.ts` (auto-gen), `src/config/exams/index.ts` (auto-gen) |
| **Passport/Visa** | `VisaPassportConfig` (shared), `CountryVisaConfig` (visa wrapper) | BiometricStudio, passport/visa pages | 40 passport files, 18 visa files | `src/config/passports/index.ts` (auto-gen), `src/config/visas/index.ts` (auto-gen) |

**Passport and visa configs share the same `VisaPassportConfig` type.** The visa system adds `CountryVisaConfig` as a wrapper with `profiles: VisaPassportConfig[]`.

**Manual has no configuration schema** — dimensions and settings are user-defined.

### 7.2 Data Flow Traces

**Exam:** `/exam/[slug]` → `page.tsx` (server) → `FORMATS.find(f => f.id === slug)` → `FormatConfig` → `<SmartEditor config={format} />` → user action → `renderCanvas()` → binary-search compression → blob → download

**Passport:** `/passport/[slug]` → `page.tsx` (server) → `getPassportConfigById(slug)` → `VisaPassportConfig` → `<BiometricStudio mode="passport" config={config} />` → user action → `renderPhotoCanvas()` / `renderPrintSheet()` → download

**Visa:** `/visa/[slug]` → `page.tsx` (server) → `getVisaCountryById(slug)` → `CountryVisaConfig` → `<VisaStudioClient country={country} />` (client) → `activeProfile` state → `<BiometricStudio key={activeProfile.id} mode="visa" config={activeProfile} />` → user action → download

**Manual:** `/manual` → `page.tsx` (server) → `<ManualEditor />` (no config) → user sets dimensions → user action → download

### 7.3 Critical Config Files (Protected During Redesign)

These files must not be modified during a visual-only refactor:

## 10. Functional Dependencies and Protected Logic

### 10.1 Canvas Coordinate System (CRITICAL)

All three active editors use this pattern:
```typescript
const scaleX = image.naturalWidth / image.width;   // display → natural
const scaleY = image.naturalHeight / image.height;
// Then: completedCrop.x * scaleX → natural coordinates
```

**Risk:** Any CSS change that alters the rendered `img.width`/`img.height` (e.g., different `max-h`, container width, padding) will produce incorrect crop coordinates. The visual crop will look correct, but the output dimensions will be wrong.

**Safeguard:** After any container CSS change, verify that the `<img>` element's `width`/`height` match expectations. Add visual regression tests that compare output image dimensions.

### 10.2 Binary-Search Compression (CRITICAL)

Each editor implements its own `findQualityForKB()` with different iteration counts:
- SmartEditor: 5 iterations
- BiometricStudio: 6 iterations  
- ManualEditor: 20 iterations + ceiling check

**Risk:** If consolidated into a shared utility, behaviour must match each editor's current precision. ManualEditor's ceiling-check (`cappedAtMax`) is unique.

### 10.3 Background Removal Lifecycle (HIGH)

All three editors follow the same pattern:
1. Optimise input (crop or resize to ≤ 1024px)
2. Call `removeBackground(inputBlob)` (WASM, potentially 5-30 seconds)
3. Composite result onto background (BiometricStudio uses `config.background.requiredHex`; SmartEditor uses `bgColor` state; ManualEditor keeps transparency)
4. Replace `imageSrc` with processed data URL
5. Reset crop to 100%

**Risk:** The component must remain mounted during the async operation. If a parent re-render unmounts the editor during BG removal, the state machine breaks.

### 10.4 ResizeObserver in BiometricStudio (HIGH)

BiometricStudio uses a `ResizeObserver` on `imageContainerRef` to position the biometric guide overlay (`overlayDims`). The overlay is positioned with `absolute` + pixel offsets.

**Risk:** Changing the CSS of the canvas wrapper, the ReactCrop container, or the `<img>` element can misalign the overlay.

### 10.5 Visa Profile Keying (HIGH)

`VisaStudioClient` renders `<BiometricStudio key={activeProfile.id} ... />`. The `key` prop forces a full unmount/remount when the profile changes, which correctly resets all state. Removing this key would cause stale state across profile switches.

### 10.6 Stamp Canvas Logic (MEDIUM)

SmartEditor's stamp feature alters canvas rendering: when `isStampingEnabled`, the photo region is compressed to 85% height and a white text strip is drawn in the remaining 15%. This logic is in `renderCanvas()` and must be preserved.

### 10.7 Filename Generation (MEDIUM)

- SmartEditor: `${config.title.replace(/\s+/g, "_")}_${activeDoc.id}_FormFoto.jpg`
- BiometricStudio digital: `${config.id}_digital_${w}x${h}.jpg`
- BiometricStudio print: `${config.id}_print_sheet_4x6.jpg`
- ManualEditor: `ManualEditor_${w}x${h}.{ext}`

These filenames may be relied upon by downstream workflows. Document them but do not change them during the redesign.

## 14. Proposed Design-System Integration

### 14.1 Token Location

With **Tailwind CSS 4** (CSS-first configuration), design tokens should be defined as CSS custom properties in [globals.css](file:///d:/Programming/Resizer/formfoto/app/globals.css) using `@theme`:

```css
@import "tailwindcss";

@theme {
  --color-surface: #F7F8FA;
  --color-surface-dark: #151B28;
  --color-primary: #315CEA;
  --color-text: #151B28;
  --color-text-muted: #6B7280;
  --color-border: #E1E5EC;
  --color-canvas-bg: #1A1D24;
  --radius-default: 0.5rem;
  --font-sans: 'Geist', system-ui, sans-serif;
  --font-mono: 'Geist Mono', ui-monospace, monospace;
  /* ... */
}
```

This leverages TW4's native `@theme` directive rather than `tailwind.config.ts` extensions. The existing `tailwind.config.ts` has an empty `theme.extend` — the CSS-first approach is the correct TW4 pattern.

### 14.2 Dark Canvas Surfaces

The editors should keep a dark neutral canvas background (`--color-canvas-bg`) even in the light-first design. This is standard in photo editing tools and improves image inspection contrast.

### 14.3 Migration Strategy

1. **Define tokens in `globals.css`** without breaking existing classes (additive only)
2. **Create shared primitives** (`Button`, `Card`, `Input`, `Badge`) that use tokens
3. **Migrate pages one at a time** from inline Tailwind to token-based classes
4. **Delete the dark theme gradient** from page backgrounds last (highest visual impact)
